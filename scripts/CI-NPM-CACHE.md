# Locked public npm mirror recovery (CI only)

The Windows CI restore still runs `npm ci --ignore-scripts --legacy-peer-deps --no-audit --no-fund` against the unchanged `ai-runtime/package-lock.json`. Its cache and `prefer-offline` setting are scoped to that single workflow step, under `RUNNER_TEMP`. No repository/user/global npm configuration is written.

If that attempt fails with HTTP 429 or 5xx for an exact locked `https://registry.npmmirror.com/<name>/-/<basename>-<version>.tgz`, `seed-ci-npm-cache.mjs` downloads the same canonical tarball path from `https://registry.npmjs.org`. It accepts only lockfile v3, exact names/versions and canonical SHA-512 SRI. Aliases, other mirrors, credentials, query/fragment, redirects, changed paths and integrity/auth/lock-resolution failures are not recovery candidates.

All selected official tarballs must pass the existing locked SRI before any `npm cache add <local-file> --offline --ignore-scripts` imports. Downloads have four workers, a 30-second per-request timeout, 32 MiB per tarball and 256 MiB aggregate limit (at most 512 packages). Imports are serial batches of eight. Any download, checksum or cache failure stops recovery; it never changes versions, locks or checksums. The original `npm ci` command is then retried once, using its integrity-addressed cache despite the lock's explicit mirror URLs. Unrelated registry URLs are never rewritten. This is not a general registry fallback.

`node --test tests/ci-npm-cache.test.mjs` includes a real offline npm install of a small self-authored tarball. The fetch seam checks the official URL, the cache is unique, the lock still names the mirror, and both root/dependency lifecycle sentinels must remain absent. It needs no network and leaves its tiny fixture for inspection. Pure tests cover rejected URLs/identities, SRI failure, bounds, concurrency and CI wiring. Running the recovery CLI itself is restricted to disposable GitHub-hosted Windows runners.

On 2026-11-09, the official zod 4.6.4 tarball was verified: 1,052,201 bytes, SHA-512 equal to the existing lock's `sha512-AXSD6hvGdvRjajG/l1cC+d6IrhH+sjmPKtYeQdJIK8MFJl3LyClzS+o/YsVC+zQZPupAaeH5skwwm8YqYH7BqA==`. A separate small offline consumer installed that real official tarball from its dedicated cache with the mirror URL unchanged in its lock, and no root lifecycle script executed. The source lock SHA-256 remained `2e3dbfaf9aba9e7989741c46692f6dd0ec239c122dad2f6eb5e796b94855f246`. This checks the reported failing package and actual cache behavior, not availability of every dependency or a completed CI build.
