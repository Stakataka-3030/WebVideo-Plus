# 预演自动存档性能修复

感谢 [NijiharaTsubasa](https://github.com/NijiharaTsubasa)（WebGAL LoveLive 专版作者）定位 planning 的自动存档热点，并提供禁用后加速的验证线索。本次独立验证确认了该机制。

## 原因与修复范围

WebGAL 在需要通知界面的舞台提交后，调用经过一秒节流的自动快速存档。存档构造会复制当前舞台状态和完整回溯记录，再复制整个存档并提交到状态仓库，随后通过 Promise 链串行写入 IndexedDB。这条自动路径关闭了缩略图生成，因此本次热点不是画面截图。

预演推进的是加速的游戏时间，节流时钟也随之推进。短时间内会反复复制不断增长的回溯记录；导出任务并不使用这个游戏快速存档槽恢复进度。

`EngineAdapter.Patch` 在已校验引擎的自动存档函数入口加入导出标记检查，在构造存档前返回。补丁只写入独立任务副本，不修改源工程、模板或正常游戏引擎。手动存档函数没有改动；导出标记不存在时，自动存档函数保留原有行为、前置条件及错误传播。任务快照和切段恢复仍沿用导出器自己的机制。

适配器版本提升到 7，并更新任务管线修订号，使重试重新准备旧的预演副本。与其他运行时修复合并时，应保留管线修订号中的 `autosave-v1` 或合并成更新的统一修订号。

## 实测

2026-11-09，使用真实 WebGAL 4.6.6、WebView2 157.0.4341.42，以及生产适配器、浏览器宿主、时钟和时间线代码。测试剧本为独立生成的 550 句对白，不包含用户素材；不能把以下倍数当作任意工程的固定加速比。

| 顺序 | 自动存档 | 预演实际耗时 | 非空快速存档写入次数 |
| --- | --- | ---: | ---: |
| 1 | 开启，移除本次入口检查作为基线 | 3929.08 ms | 275 |
| 2 | 关闭 | 1991.17 ms | 0 |
| 3 | 关闭 | 2005.43 ms | 0 |
| 4 | 开启 | 4238.98 ms | 275 |

平均耗时从 4084.03 ms 降至 1998.30 ms，减少约 51%，约为原速度的 2.04 倍。基线中，仅存档构造、复制与状态提交的同步部分就耗时 1616.9 / 1742.8 ms。四轮剧情时长均为 275050 ms，完整时间线结果的 SHA-256 一致：`063161e2b349ad75324a37822f4bf94f4dfbcd1454605cb866b698e4f2e82d51`。未捕获浏览器异常，源引擎哈希未变。原始汇总见[验证记录](verification/autosave-planning-20261109.json)。

另外对已固定哈希的 WebGAL 4.6.4 准备版、MyGO 3.2.1 和 WebGAL 4.6.6 运行生产适配器，并执行真实自动存档函数的回归：导出时不构造或持久化存档；导出标记不存在时正常存档；标题页、初始语句和场景写锁检查保持原样；真实异常继续传播。

## 复验

在 Windows 上提供独立的、受支持的固定版本引擎，以及已准备的 WebView2 支持包：

```powershell
.\tests\autosave-planning-native.ps1 -EngineRoot C:\test\webgal466 -SupportPackage C:\test\package
```

脚本从当前生产源码编译探针，交替执行两组 A/B，输出结果、引擎身份和函数回归结果。每次复验建议使用新的 `-OutputRoot`。基线仅在探针拥有的副本中移除本次检查。`-ContractOnly` 可验证其他引擎的入口兼容性和 JavaScript 语法，不运行 WebView2 预演；MyGO 另传 `-Engine mygo`。

本次完成的是预演性能修复验证，尚未做与 Live2D 生命周期修复合并后的完整用户工程预演或视频编码。WebGAL 4.6.5 的兼容性仍需单独提供其固定版本运行时复验。
