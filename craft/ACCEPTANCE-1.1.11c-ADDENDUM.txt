WebVideoCraft 1.1.11c native confirmation acceptance addendum
Review date: 2026-10-04 UTC

Decision

The modal-retention assertions do not block release of the exact tested
1.1.11c candidate. The observed official-install confirmation is accepted for
its tested consent, cancellation, repeat/reload and refusal-recovery behavior.
No source change, rebuild, version increment or official-installer rerun is
needed for this finding. Publication remains a separate release decision.

This addendum corrects the acceptance criterion, not the raw test results.
The original report and JSON assertions remain immutable: they accurately
record that About/Details did not remain open. The previous blanket requirement
that these informational dialogs must survive until an answer was too broad.
The exact source's ACCEPTANCE-1.1.11c.md, update/README.md and handoff should be
read together with this later native assessment. Their broad no-display-close
wording is corrected to: the adapter does not explicitly close update displays
before approval; upstream displays may close through their own UI lifecycle.

Why Details closes

The pinned official beta.2 UpdateDetailsModal.vue, lines 41-44, explicitly sets
open=false before invoking onUpdateNow. Its official component spec, lines
120-126, expects Update Now to close the dialog. The extracted real host bundle
independently confirms that same ordering. Closing this informational Details
panel is therefore expected official behavior. It does not imply consent to
the enhancement's later installation request.

Why About is not a proven product defect

About disappeared in the scoped native test, but the cause is not established.
The test replaces the action at a button-capture seam with the exact compiled
native controller and an inert service. The driver selects the last globally
visible matching update button, without restricting it to About's DOM; the
pinned About component itself has an icon-only check-for-update action. This
cannot establish the untouched About handler's behavior or attribute dismissal
to a particular product event. The report's About-retention failure is retained
as an observation with this test-attribution limit.

The consequence observed was dismissal of an informational panel. The owned
confirmation stayed visible with Cancel initially focused. Real Cancel and
Install controls worked, and pointer-locked native-modal diagnostics also
passed Escape. Native QA found no lingering focus/click block, premature host
closure, document damage or unusable confirmation. About's disappearance alone
therefore does not warrant another binary revision.

Corrected acceptance criterion and observed outcome

1. The installation request must have a visible, usable explicit confirmation.
   Passed with the actual WebView HTML dialog and real mouse input; confirmation
   results were not replaced. Cancel initially had focus.
2. Before affirmative consent, no update.prepare, commit or abort request,
   host closure or installer execution may occur. Passed while unanswered and
   through Cancel, Escape, repeats, detached old controls and page reload in
   the documented inert-transport fixtures. Read-only checking, the user-led
   download and resource cleanup are not installer execution.
3. Only the current dialog's explicit Install action may proceed. Passed:
   one update.prepare occurred after the real Install click, followed by one
   update.abort when the inert transport refused preparation. There was no
   commit, normal-window-close call or installer in that flow.
4. Cancellation/refusal must preserve Craft and the document and release its
   pending route. Passed within the documented native cases. A native display
   panel that closes through its own UI lifecycle need not be reconstructed.
5. Genuine future signed installation must not be claimed from an inert test.
   Still unproven. The three historical acceptance flags remain false.

Other retained acceptance and limits

The exact candidate passed 822 Node tests and 173 composed checks. Actual own
updater check/download/hash/open, dirty/busy prevention, independent live-session
Setup mutation refusal and normal Setup cancellation passed with explicitly
local release inputs. Anogo preview/apply/undo and recommended NVENC export
passed; the short video was 1280x720, 30 fps, 4.7 seconds and 141 frames.

The unchanged helper retains the earlier 33 Windows C# contract assertions and
8 actual inert-helper cases by source identity. Native cleanup restored all
392 original file hashes and four registry groups; no owned process or lock
remained. No official NSIS was run for this retest.

Runtime officialAutoInstallEnabled=true remains the user's selected policy.
updateObserverValidated=false, sameNameUpdateValidated=false and
officialCleanUpdateValidated=false remain truthful historical evidence.
There is no newer genuine signed target for a full forward-update acceptance
run. Official installation is enabled with that disclosed uncertainty; an
updated host needs a compatible enhancement installer for explicit re-adoption.
Neither automatic enhancement remount nor full future-update success is claimed.
